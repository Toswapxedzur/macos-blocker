# macosBlocker — Mac Vault (native macOS app)

> 🤖 **AI protocol:** Read `../package-info.md` (group), the group `AGENTS.md`, and `../misc/project-memory/PROJECT-MEMORY.md` before working here. Update this file when the folder changes. Never delete without owner consent; keep secrets out of git.

- **Independent Classifier dials (owner 2026-10-01):** each group owns its model tier, strictness and house rules. Core tier/download cards and strictness choices stay visible; More contains optional tag-count bounds; global dials and inheritance are retired. Existing effective values reconcile once into concrete group settings.

- **Growing lists (owner 2026-10-01):** bound accumulating collections inside scroll boxes, including Knowledge, API keys, editor chips and Activity members. `docs/LIST-CONTAINMENT.md` records the full UI inventory and mini1 regression fixtures. Short lists fit their contents; item counts are not truncated.

- **Custom-rule logs (owner 2026-10-01):** the Log panel contains only `v.log()` output, independently retained by immutable group ID (200 entries per rule). Clear and Download operate on the selected rule. Engine errors and collection/transport diagnostics stay in developer diagnostics. Browser feed tests: `customBlocker/tests/runner-rule-log-isolation.js`; native persistence tests: `macosBlocker/Tests/RuleLogShim.test.js`.

- **What:** the native macOS member of the suite (public name **Mac Vault**): Swift policy engine, WebView editor (the extension's own popup, synced into `Sources/MacBlockerWebUI/WebAssets` by `sync-webui.sh`), app inventory + enforcement adapters, and the **local Vault hub host** (dev `ws://127.0.0.1:18787`, prod 8787) the **Vault Classifier component** (`classifier/` — on-device tagging, shown as the window's **Classifier** page and started at launch so tags keep flowing after the window closes), plus an **MCP HTTP server for agents** (dev port 18788 = the `vault-dev` MCP entry in Claude's config; only reachable while the app runs).
- **MCP tools (36 on 2026-09-27; results are JSON, refusals from `ToolRefusals.swift`):** 16 Vault group tools (`VaultMCPTools.swift`: list/get/set/create/delete/move groups, add/remove_application, lock/unlock/set_lock_gates, snooze/end_snooze, set_settings, delete_all_groups, run_custom_rule — its description carries the Mac rule reference — apps only, never a website), 3 link tools (`list_links` / `link_groups` / `unlink_group`), the classifier's `classifier_state` / `classifier_action` / `classifier_actions`, and 13 browser-extension tools (`extension_state`, `extension_create_group` / `set_group` / `delete_group` / `move_group`, lock / unlock / set_lock_gates / delete_all, snooze / end_snooze, `extension_set_global`, `extension_run_custom_rule` (with the browser rule reference); `ExtensionMCPTools.swift`: each relays one `browser-request` through `ConnectionHub.sendBrowserRequest` to the connected browser's service worker, which applies the popup's own sanitizers; needs exactly one browser connected or a `browser` argument — a program name such as `chrome`; since 2026-09-25 the hub refuses a second connection from the same browser program with `duplicate-program` — a test rig's Chromium cannot sit beside the owner's Chrome, only one of them is connected at a time) (see `classifier/package-info.md`, "MCP surface"). Bearer token = HMAC of the hub secret (`LocalHubAuthentication.mcpBearerToken`); if a client config holds a stale token the endpoint answers 401 — the client config must be refreshed from the current secret (`~/.claude.json` was refreshed by hand 2026-09-23, backup `~/.claude.json.bak-mcp-token-2026-09-23`).
- **Own git repo:** `Toswapxedzur/macos-blocker`, branch `main`; releases `v0.0.1`, `v0.0.2`, `v0.1.0`, `v0.2.0`, `v1.0.0` (+ `release/` branches; 0.1.0 and 0.2.0 are retroactive milestones, 1.0.0 is the first with the classifier). Version source of truth = `XcodeProject/project.yml` (`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`).
- **Shared delivery (owner 2026-10-01):** `AGENTS.md` routes worktrees to the project rules. Completed Mac work integrates into `integration/local-delivery` at `~/Desktop/agentic/worktrees/vault-delivery/macosBlocker`; `~/Desktop/agentic/tooling/bin/vault-delivery` verifies the exact combined commit on mini1 and relaunches the laptop app. `run-mac-vault.sh` dispatches there through the common Git configuration. See `scripts/development/README.md`.
- **Build/test:** `swift build`, `swift test` (SwiftPM, `Package.swift`; needs Homebrew `llama.cpp` for the classifier's engine; the classifier's own 229 tests run with `swift test --package-path classifier`); dev launch `run-mac-vault.sh` (signs with a Developer ID identity). Release DMG pipeline in `scripts/release/` (see `RELEASE.md`).
- **Folders:** `classifier/` (the Vault Classifier component — a nested SwiftPM package with its own `package-info.md`; merged from the former `vault-classifier` repo with full history), `Sources/` (`MacBlockerCore`, `MacBlockerAppFeature`, `MacBlockerWebUI`, `MacBlockerMacControl`, `MacBlockerPanel`), `Tests/`, `XcodeProject/` + `XcodeScaffold/` (app + Safari-extension targets, `SafariWebExtensionHandler.swift`), `Assets/Branding/` (official Mac icon sources), `i18n-docs/`, `LEGAL/`, `dist/` + `release/` (artifacts), `tools/`. `MacBlockerWebUI/WebAssets/activity-time-bins.js` is the interval-overlap adapter for Usage's configurable ordered chart; `Tests/ActivityTimeBins.test.js` verifies boundaries and browser/site attribution with Node.
- **One web view, one document (owner 2026-09-28):** the window is a single WKWebView showing the synced editor (`popup.html`). The Classifier and Activity are scenes of that same page (`WebAssets/scenes.js`/`scenes.css`, Mac-only; `sync-webui.sh` adds their tags), each in its own shadow root so their stylesheets never meet; the Vault/Classifier/Activity tabs switch inside the page and only tell the native side (`scene-shown` → `.vaultSceneShown`). `WebScene` lets a component install its message handler/URL scheme into the one configuration; the Classifier's files are served at `cbasset://app/classifier/…` from its own bundle, Activity's (`activity.js`/`activity.css`) are Mac WebAssets. (The former three stacked web views fought over the mouse cursor.)
- **Activity groups (owner 2026-09-29):** users group apps and websites (`ActivityGroups.swift`, `groups.json`); any group can be viewed in Details, a **merge** group also replaces its members everywhere in one colour (an item: many groups, at most one merge group). Colours are permanent per app/site/group (`colors.json`). AI tools: `list_activity_groups` / `save_activity_group` / `delete_activity_group` (`ActivityMCPTools.swift`). See `docs/ACTIVITY-LOG.md` §6b.
- **Mirror rule:** `Sources/MacBlockerCore/Resources/{rule-core,event-sandbox,group-scopes,group-actions,parental-pin,platform-profiles}.js` must stay byte-identical to customBlocker (a test checks) — refresh with `./sync-webui.sh`.
- **Custom rules (owner 2026-09-27):** bare-bone, no helpers. `RuleRuntime.swift` runs `rule-core.js` + `custom-rule-runtime.js` (Mac Vault's actions: `v.block`/`v.quit`/`v.open` — apps only, never a website) in JSC with a 1.2 s execution limit; `MacEnforcementBridge` sends "tick" {frontmost, running — every app incl. menu-bar/background}, "app" {launch|quit|focus|blur|hide|unhide}, "snooze", "panel", "file", and runs what was last Run (`activeEventSource`); state lives in the store's `cbRuleState`. `SafariCustomRuleBridge` hosts the *browser's* engine for Safari. The WebAssets editor is a synced copy of the customBlocker popup since 2026-09-24 (`./sync-webui.sh`; desktop-only sections are gated by `body.is-native-desktop`) — never hand-edit a synced file; only `chrome-shim.js`, `activity.html`, `icons/` and `manual/` are Mac-specific.
