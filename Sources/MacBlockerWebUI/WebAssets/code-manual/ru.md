# Руководство по коду Mac Vault

[Руководство пользователя](../manual/ru.md)

## Контракт правила

Source: одно функциональное выражение `(on, v) => { ... }`. Поддерживаются только синхронный JavaScript и приведённый ниже API; обратные вызовы планирования JavaScript, сеть, нативные системные API и доступ к страницам браузера не поддерживаются. Правила по времени используют описанные ниже управляемые таймеры/счётчики либо `ev.now` и события. Safari используют browser code manual и выполняются в собственном контейнерном приложении Safari Vault.

- Изменения сохраняются как черновик; **Run** активирует правило и включает группу. Замороженные группы не могут выполнить Run. Пустой source выгружает правило.
- Успешный Run заменяет handlers/panels и очищает app-block set этой группы, сохраняя `v.state`. Ошибка компиляции/регистрации сохраняет предыдущее правило; timeout может его остановить. Restart снова регистрирует последний активированный source; closure variables и app-block sets сбрасываются.
- Регистрация может инициализировать state, регистрировать handlers, показывать panels и записывать log. Действия с приложениями/файлами и emits должны быть в handlers; очередь регистрации отбрасывается.
- Disable приостанавливает handlers и удаляет panels/app blocks. Enable восстанавливает загруженное правило и сохранённые panels/blocks. Delete удаляет handlers/state/effects. Ранее закрытые приложения не открываются повторно; запись файлов не отменяется.
- Events не ограничены обычными целями группы; выбирайте приложения в правиле. Actions ставятся в очередь и применяются после dispatch. Исключение останавливает handler, не отменяя его state/actions; последующие handlers могут продолжить работу. Только file actions имеют result events.

## Управляемые таймеры и скользящий учёт использования

`v.timer(id, {direction:"down", durationMs:300000})` создаёт или возвращает именованный таймер обратного отсчёта, изначально приостановленный. Для таймера прямого отсчёта используйте `{direction:"up"}`. Объект предоставляет `start()`, `pause()`, `resume()`, `reset()` и `snapshot()`. Start/resume идемпотентны; reset возвращает таймер в приостановленное состояние с нулевым прошедшим временем. Поля снимка включают `ready`, `error`, `elapsedMs`, `remainingMs` (null для прямого отсчёта), `running` и `completed`.

Запущенные таймеры отсчитывают реальное время, даже когда приложение/браузер закрыты или правило отключено. Завершённый обратный отсчёт доставляет `timerEnded` с `{id, direction, durationMs, generation, incarnation}` один раз на каждое воплощение и поколение таймера каждому участнику при следующем выполнении его правила; Run не повторяет это событие. Доставка зависит от событий хоста; это не будильник реального времени. Добавьте `{type:"timer", timerId:"focus", label:"Focus"}` в панель, чтобы отображать таймер через существующий текстовый элемент управления.

`v.rolling(id, {windowMs:3600000, limitMs:600000})` создаёт или возвращает именованный счётчик активного использования. `assign({websites:["youtube.com","reddit.com"], apps:[]})` заменяет назначенные цели этого участника. Нативные правила могут вместо этого назначать идентификаторы приложений соответствующей платформы. Домены включают поддомены. Один счётчик объединяет свои цели; у других идентификаторов независимые лимиты. `snapshot()` возвращает `ready`, `error`, `usedMs`, `remainingMs`, `available` и `nextReturnAtMs` (ближайшую миллисекунду, когда истекает какой-либо записанный отрезок использования). `available(target?)` также проверяет назначение, если указана цель. `reset()` очищает историю этого объекта.

Учитывается всё наблюдаемое использование, соответствующее условиям, включая использование сверх лимита; сам счётчик не блокирует страницу/приложение. Перекрывающиеся интервалы видимости страниц учитываются один раз, а нативные приложения учитывают наблюдаемое использование на переднем плане. Отключённые правила не добавляют использование; история по-прежнему истекает точно на границах интервалов. Доступность возвращается только тогда, когда оставшаяся история становится меньше лимита. Замеры по периодическим сигналам активности ограничены пятью секундами; промежутки закрытия/отключения не создают активность. События, отправленные пользователем, не добавляют использование.

Одинаковые идентификаторы объектов в связанных пользовательских группах используют один локальный нативный хаб как полномочный источник состояния. Связывание объединяет историю и назначения счётчиков и сохраняет состояние таймера инициирующего участника; несовместимые конфигурации не допускают связывание. Каждый участник получает собственное событие завершения. Потеря соединения делает общие счётчики недоступными и приводит к отклонению команд таймера до получения актуального состояния от полномочного источника. При разрыве связи каждый участник сохраняет итоговое общее использование и состояние таймера, восстанавливает свои цели и отбрасывает команды старой связи. Хаб хранит итоговый снимок, пока вернувшийся участник не сохранит и не подтвердит его; ожидающие передачи завершаются до того, как станет доступна новая связь.

Именованные объекты сохраняются после Run и перезапуска в зарезервированном `v.state.$vaultTime`; не изменяйте это поле напрямую. Удаляйте их явно через `v.removeTime(id)`. Идентификаторы содержат 1–80 букв ASCII, цифр, `_` или `-`; зарезервированные имена свойств отклоняются. До 32 объектов делят лимит состояния правила в 64 КиБ UTF-8. Длительность задаётся целым числом миллисекунд, не более 365 дней. Скользящая история ограничена 1024 минутными корзинами и 2048 объединёнными интервалами. Ошибки вместимости истории оставляют счётчик недоступным до явного сброса; неверные конфигурации и слишком большие сохранения сообщают об ошибках, не стирая сохранённые данные.

```js
(on, v) => {
  const timer = v.timer("focus", {durationMs: 300000});
  v.panel("focus", {controls: [
    {type: "timer", timerId: "focus", label: "Focus"},
    {id: "start", type: "button", label: "Start"},
    {id: "pause", type: "button", label: "Pause"},
    {id: "reset", type: "button", label: "Reset"}
  ]});
  on("panel", ev => {
    if (ev.data.eventName !== "click") return;
    if (ev.data.controlId === "start") timer.start();
    if (ev.data.controlId === "pause") timer.pause();
    if (ev.data.controlId === "reset") timer.reset();
  });
  on("timerEnded", ev => v.log("Finished", ev.data.id));
}
```

## API

- `on(type, handler)` → логическое значение. Регистрирует `handler(ev)`; несколько обработчиков выполняются в порядке регистрации. False означает неверные аргументы или достижение лимита обработчиков. `ev = { type: string, now: number, origin: "host" | "user" | "rule", data }`; `now` — время Unix в миллисекундах. У ввода нативной панели `origin: "user"`; у `v.emit` — `origin: "rule"`.
- `v.state`: изменяемый JSON-объект, сохраняемый после event dispatch. Инициализируйте отсутствующие fields, не перезаписывая текущий state. Присваивание non-object или массива сбрасывает его в `{}`; несерилизуемые/слишком большие обновления не сохраняются.
- `v.log(...values)`: добавляет записи в Log этой группы. Сбои выполнения и доставки появляются как явные записи об ошибках в той же ленте. Logs/Clear независимы для каждой группы. Ошибки загрузки также отображаются в статусе Run; частично выполненные события автоматически не повторяются.
- `v.emit(type, data)`: ставит JSON-копию `data` в очередь handlers группы после текущего event с новым `now`; это не синхронный вызов.
- `v.panel(id, spec)`: заменяет именованный плавающий panel группы; null `spec` удаляет его. См. Panels.
- `v.file(op, path, payload?)` → строка request ID. См. Files.
- `v.store(request)` → строка с ID запроса. См. записи группы.
- `v.block(appId, on)`: true поддерживает блокировку приложения, false снимает блокировку группы. Блокировки включённых групп объединяются; вызов не может снять цель другой группы. Блокировка запрашивает обычный выход и повторяет попытку с интервалом из Settings; она не мешает запуску процесса и не гарантирует, что приложение примет Quit.
- `v.quit(appId)`: один обычный запрос на выход с той же защитой/повтором; без постоянной блокировки.
- `v.open(appId)`: просит macOS открыть установленное приложение; callback успеха нет.

Остальные вызовы возвращают `undefined`. App IDs — идентификаторы пакетов (например, `com.valvesoftware.steam`), доступные в событиях. Block/Quit могут воздействовать на приложения Apple и целые браузеры. Они игнорируют идентификатор пакета Mac Vault и его помощники, включая другие приложения с той же идентичностью, а также пустые идентификаторы. Panel IDs/state принадлежат группе, а не отображаемому имени.

## События

Обозначения payload ниже описывают типы и не являются исполняемым кодом. `?` отмечает необязательные fields.

```text
tick (~1 second): { frontmost: App | null, running: App[] }
app: { kind: "launch" | "quit" | "focus" | "blur" | "hide" | "unhide",
       appId: string, name: string, previousAppId?: string | null }
snooze: {}
panel: { panelId: string, controlId: string, eventName: string,
         value: string, values: { [controlId: string]: string } }
file: see Files
record: { requestId: string, ok: boolean, op?: string, key?: string,
          record?: Record | null, entries?: Header[], next?: string | null,
          deleted?: number, error?: string }
App = { appId: string, name: string }
```

- `tick` приблизителен; используйте timestamps, а не счётчик ticks. Running включает foreground-, menu-bar- и background-процессы `.app` с bundle IDs; не все процессы Unix. Frontmost может быть null или иметь пустой app ID.
- `app` сообщает о наблюдаемых изменениях жизненного цикла до event `tick` этого тика. Только focus включает `previousAppId` (null, если неизвестен). Names — отображаемые, а не стабильные IDs.
- `snooze` означает, что нажата кнопка Snooze группы. Само по себе это не вызывает паузу.
- Ответы file направляются запросившей группе. Сопоставьте `requestId`, проверьте `ok` и установите deadline с ticks: ответы могут потеряться при перезагрузке/отключении правила. Request IDs могут повторяться после Run; ожидающие requests не являются долговременной работой.

## Панели

```text
spec = { title?: string, description?: string, controls?: Control[],
         position?: "top-left" | "top-right" | "bottom-left" | "bottom-right" | "center",
         width?: "small" | "medium" | "large" | number }
Control = { id?: string, type?: string, label?: string, value?, disabled?: boolean,
            ...type-specific fields below }
```

По умолчанию: внизу справа, ширина 300px; пресеты small/medium/large — 220/280/360px; числовая ширина ограничена 180–520px и принимает pixel strings. Native panels/sections располагают controls вертикально; browser layout, alignment, role, autofocus и control-dimension fields не влияют на native renderer.

IDs нормализуются до ASCII letters/digits/`_`/`-` (макс. 80); выбирайте уникальные стабильные IDs. Пропущенный control ID становится `control-N`; пропущенный/неизвестный type становится text. Пропущенные text/lists пусты; disabled равно false. Каждый вызов заменяет полную spec. Явный `value` имеет приоритет; если он пропущен, используется последний event value, затем нормализация type. Native events предоставляют strings: преобразуйте их в объявленный value type перед обновлением panel. Неизвестные fields отбрасываются; цвета/fonts/CSS panel принадлежат Vault.

Поля и начальные значения элементов управления:

- `text`: string `text`; по умолчанию label. `html`: string `html`, очищается и отображается как обычный текст на Mac.
- `button`: `label`, необязательный `action: "submit" | "cancel" | "close"`. Значение click — строка action или пустое. Actions ничего не отправляют/не закрывают автоматически.
- `checkbox`, `toggle`: boolean `value` (по умолчанию false); event value — `"true"`/`"false"`.
- `select`, `radio`: `options: (string | { value: string, label?: string })[]`; string value (по умолчанию пустой). Пустые option values удаляются; labels по умолчанию равны value. Обновляйте типизированное значение panel после выбора.
- `textInput`, `textarea`: string value (по умолчанию пустой); у textInput есть `placeholder`; textarea `rows` 1–12 (по умолчанию 3). Native textarea игнорирует placeholder.
- `numberInput`, `range`: numeric value (по умолчанию 0), `min`, `max`, положительный `step`. При обновлении panel values ограничиваются границами; неуказанные границы нормализации — −1000000…1000000. Native numberInput — текстовый ввод: самостоятельно проверяйте `Number(event.value)`; min/max/step не ограничивают набор. Native range по умолчанию 0…100 с шагом 1.
- `date`, `time`: текстовый ввод; начальные форматы `YYYY-MM-DD`, `HH:MM`/`HH:MM:SS` (неверные форматы становятся пустыми). Самостоятельно проверяйте изменения. `color`: `#RRGGBB` (по умолчанию `#000000`).
- `pin`: строка цифр; `length` 3–12 (по умолчанию 6), `masked` по умолчанию true, `autoSubmit` false. `section`: `text`, `controls`; child sections на depth 3 не имеют children (root controls depth 0).

Panel events: обычные поля ввода отправляют `change`; buttons — только `click`; PIN отправляет `change` и `submit`, когда autoSubmit заполнен. Native mount/unmount/focus/key events отсутствуют. Values — strings, включая numbers/booleans. `values` содержит текущие значения ввода из отрисованного снимка и может отставать от инициировавшего изменения; `value` идентифицирует это изменение. Сохраняйте его в `v.state` и отображайте типизированные values для надёжных форм. Non-click events объединяются в течение 100ms на control; не считайте их нажатиями клавиш.

Ограничения текста: title/label 240; description/text 1000; HTML 20000; placeholder 500; input text 2000; другие value strings 512; option value/label 256. Превышение обрезается.

## Файлы

`op`: `"read"`, `"write"`, `"append"`, `"list"`, `"exists"`. Требуется **Папка пользовательских правил** в Settings и её разрешение.

- `path` относительный; `/` разделяет directories. Сегменты допускают ASCII letters/digits, пробелы и `_.,@()-`; без начальной точки, `.`/`..`, absolute path или URL. Расширения: `.txt`, `.csv`, `.json` (без учёта регистра). List path — каталог; `""` перечисляет выбранный root. Пути за пределы выбранной папки, в том числе через symlinks, отклоняются.
- Read возвращает текст UTF-8. Write заменяет/создаёт; append создаёт/добавляет без автоматического newline. При записи создаются родительские каталоги. String payload записывается буквально; остальные JSON payloads сериализуются; null/пропуск означает пустой текст. Разбор JSON/CSV — задача правила. Максимальный размер файла: 1048576 UTF-8 bytes.
- List возвращает непосредственно видимые подкаталоги и поддерживаемые файлы. Entries: `{ name: string, path: string, kind: "directory" | "file", extension?: string }`; для файлов extension включает точку. Exists возвращает boolean для поддерживаемого file path.

```text
file.data = { requestId: string, op: string, path: string, ok: boolean,
              text: string | null, entries: Entry[] | null,
              exists: boolean | null, error: string }
```

Неиспользуемые result fields равны null; при успехе error пустой. Ошибки включают invalid-path, unsupported-file-type, папка недоступна, файл отсутствует и file-too-large. Рассматривайте error как string, а не полный фиксированный enum. Transaction API нет; сериализуйте read-modify-write для каждого path.

## Записи группы

`v.store(request)` запускает асинхронную операцию JSON-записи внутри обработчика. Записи принадлежат группе, сохраняются после Run и перезапуска и удаляются вместе с группой. У связанных групп отдельные хранилища. Правило выбирает ключи, значения, версии, инвалидацию кеша и приоритет обратной связи. Правила Mac и браузера используют один API, но у каждого приложения/браузера свое хранилище.

| Request | Result |
|---|---|
| `{op:"get", key}` | `record` или `null` |
| `{op:"put", key, value, version?, ifRevision?}` | сохраненный `record` |
| `{op:"delete", key, ifRevision?}` | `record: null` |
| `{op:"list", prefix?, after?, limit?}` | отсортированные `entries` и `next` |
| `{op:"clear", prefix?}` | число `deleted` |

Запись имеет вид `{value, revision, version, updatedAt}`. Непрозрачная revision меняется при реальной записи; `version` — метаданные вызывающей стороны. `list` возвращает заголовки без значений; `get` читает запись, `after: next` запрашивает следующую страницу. Без `put`/`delete`, `ifRevision` put/delete безусловны; `null` требует отсутствия ключа, строка revision — точного совпадения. Конфликт возвращает `ok:false`, `error:"store-conflict"` и текущий `record`, чтобы запоздалый автоматический ответ не перезаписал отзыв пользователя. `v.context.revision` — непрозрачный маркер конфигурации правила, который можно включить в его версию; фреймворк не задает политику кеша.

Ограничения: ключ 1–2048 символов, version ≤128, JSON-значение ≤64KiB, глубина ≤32, 10000 ключей на группу, весь документ16MiB. `list` возвращает максимум100 заголовков и96KiB на страницу. До32 запросов на группу и128 запусков в секунду всего; перегрузка выдает один `store-busy` на группу в секунду и отбрасывает остальные. Ошибки хранилища возвращают `ok:false`; будущий/поврежденный документ сохраняется и сообщает `store-unavailable`. Автоматических повторов и очистки нет. Для сроков используйте ticks.

## Ограничения

На событие в каждой группе: 256 действий в очереди, 200 вызовов журнала, 64 отправки событий; избыток отбрасывается. На правило: 1000 обработчиков, 24 панели; каждый список элементов управления содержит 32 записи, а каждый выбор — 64 варианта; избыток игнорируется/обрезается. Цепочки отправки событий останавливаются после 16 поколений. Лимит сериализованного состояния: 65536 байт UTF-8. Регистрация и все обработчики каждого события в сумме должны выполняться менее 1 секунды; повторные превышения или жёсткий тайм-аут останавливают правило до Run. Log хранит 200 записей на группу. Отсчёт времени/ответы работают по мере возможности, без гарантий реального времени.

## Полное правило

Steam заблокирован, кроме пятиминутной паузы, запущенной кнопкой Snooze или кнопкой её panel:

```javascript
(on, v) => {
  v.state.pauseUntil ??= 0;
  const pause = ev => { v.state.pauseUntil = ev.now + 300000; };
  v.panel("pause", { controls: [{ id: "pause", type: "button", label: "Pause 5 min" }] });
  on("snooze", pause);
  on("panel", ev => {
    if (ev.data.panelId === "pause" && ev.data.controlId === "pause" && ev.data.eventName === "click") pause(ev);
  });
  on("tick", ev => v.block("com.valvesoftware.steam", ev.now >= v.state.pauseUntil));
}
```


## Вызовы ИИ из работающего правила

Каждая custom group выбирает подключение/модель и reasoning effort в **AI calls**. Правила Mac и браузера используют один API; браузерным запросам нужен подключенный Mac Vault, учетные данные поставщика остаются там. Связанные группы совместно используют выбор и необязательный дневной лимит. Пустое поле означает отсутствие лимита группы; лимиты аккаунта сохраняются. Лимит считается по UTC-дню, переживает перезапуск и учитывает отправленные попытки, включая неудачные. Link объединяет прежнее использование; unlink сохраняет его.

`v.ai({ prompt, input? })` немедленно возвращает request ID. Вызывайте внутри обработчика, не при регистрации правила. `input` может быть любым JSON; prompt/input ограничены20KB каждый. Ответы приходят в событиях `ai`: `{requestId, ok, text, citations, error}`. Успешный текст до48KB; цитаты `{url,title}`. Сохраняйте видимые и кликабельные ссылки на источники в ответах веб-поиска. Поиск всегда доступен модели. Фиксированного срока приложения нет; параллелизм ограничен; нет fallback поставщика и автоматического повтора. Ответы — данные, они не исполняются как JavaScript; правило решает, какие существующие действия выполнять.

Для панели с кнопкой `ask` и полем `note`:

```javascript
(on, v) => {
  let pending = null;
  on("panel", ({ data }) => {
    if (data.controlId !== "ask" || pending) return;
    pending = v.ai({ prompt: "Summarize this text.", input: data.values?.note ?? "" });
  });
  on("ai", ({ data }) => {
    if (data.requestId !== pending) return;
    pending = null;
    if (!data.ok) { v.log("AI request failed:", data.error); return; }
    v.log(data.text, data.citations);
  });
}
```

Незавершенные вызовы не воспроизводятся после перезапуска. Run, отключение/повторное включение и удаление отбрасывают старые ответы; отключенный браузер сообщает `ai-unavailable`. Другие ошибки: `ai-not-configured`, `ai-invalid-input`, `ai-busy`, `ai-daily-limit`, `ai-request-failed`, `ai-usage-storage-unavailable`. Неудачные вызовы не заменяют сохраненный правилом предыдущий результат. Лимит состояния по-прежнему64KB.

Варианты без учетных данных доступны через `rule_ai_models` на Mac или `settings-rule-ai-models` в браузере; настройте `ruleAI` существующим путем set-group. Поля: `providerModel`, `accountID`, `reasoningEffort` (`default`, `low`, `medium`, `high`), `dailyRequestLimit` (null или1–100000). Используйте возвращенный вариант; не помещайте ключ или URL поставщика в исходный код правила.
