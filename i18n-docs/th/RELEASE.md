# คู่มือการเปิดตัว Mac Vault

คู่มือนี้เป็นไปตามสคริปต์บิลด์ที่เช็คอิน โดยเจตนาไม่มีข้อมูลประจำตัวการลงนามส่วนตัว โปรไฟล์การรับรอง รหัสผ่าน หรือข้อมูลบัญชี

##ก่อนปล่อย

1. รัน `swift test` จากรูทของพื้นที่เก็บข้อมูล
2. ตั้งค่าเวอร์ชันรีลีสและหมายเลขบิลด์ในการกำหนดค่าโปรเจ็กต์/บิลด์ที่ได้รับการควบคุม
3. ทบทวนคู่มือภาษาอังกฤษ คู่มือฉบับแปล และการตรวจสอบการแปลของบรรณาธิการ
4. ตรวจสอบสาขาการเผยแพร่ แท็ก และนโยบายเหตุการณ์สำคัญก่อนเผยแพร่อาร์ติแฟกต์

## ไปป์ไลน์ DMG ของเว็บไซต์

สคริปต์อยู่ใน `scripts/release/` ค่าเริ่มต้นสามารถแทนที่ได้ด้วยตัวแปรสภาพแวดล้อม รวมถึง `APP_NAME`, `BUNDLE_ID`, `TEAM_ID`, `SIGNING_IDENTITY`, `NOTARY_PROFILE`, `VERSION` และ `BUILD_NUMBER`

รันไปป์ไลน์ที่สมบูรณ์บนเครื่องลงนามที่กำหนดค่าไว้เท่านั้น:

```bash
VERSION=<version> BUILD_NUMBER=<build> scripts/release/full_release_dmg.sh
```

ไปป์ไลน์ประกอบด้วยสคริปต์การสร้าง การลงนาม DMG การรับรองเอกสาร และสคริปต์การตรวจสอบที่มีอยู่ ถือว่าเอาต์พุตนั้นเป็นตัวเลือกที่เผยแพร่จนกว่าขั้นตอนการตรวจสอบจะสำเร็จ

## เป้าหมายการกระจาย Xcode

สร้างโปรเจ็กต์ Xcode จาก `XcodeProject/project.yml` กำหนดค่าทีมการลงนามที่เหมาะสมและความสามารถในสภาพแวดล้อมที่ได้รับอนุมัติ จากนั้นเก็บถาวรเป้าหมายที่เกี่ยวข้อง อย่าส่งข้อมูลประจำตัวที่สร้างขึ้น การจัดเตรียมไฟล์ หรือโปรไฟล์การรับรองเอกสาร

## หลังจากการเปิดตัว

1. สร้างแท็กเวอร์ชันที่ไม่เปลี่ยนรูปและสาขาการเผยแพร่แบบถาวรตามนโยบายการจัดการการเผยแพร่
2. เผยแพร่อาร์ติแฟกต์การเผยแพร่และการตรวจสอบรวม
3. อัปเดตรีจิสทรีการเผยแพร่ต่อสาธารณะหลังจากที่ URL ของวัตถุเป็นที่สิ้นสุดแล้วเท่านั้น
4. เก็บบันทึกประจำรุ่นเป็นภาษาอังกฤษ เว้นแต่จะมีบันทึกประจำรุ่นฉบับแปลที่ได้รับการตรวจสอบแล้ว
