# Mac Vault リリースガイド

このガイドは、チェックインされたビルド スクリプトに従います。これには、個人の署名 ID、公証プロファイル、パスワード、アカウント データは意図的に含まれていません。

## リリース前

1. リポジトリのルートから `swift test` を実行します。
2. 管理対象のプロジェクト/ビルド構成にリリース バージョンとビルド番号を設定します。
3. 英語マニュアル、ローカライズされたマニュアル、および編集者の翻訳監査を確認します。
4. アーティファクトを公開する前に、リリース ブランチ、タグ、マイルストーン ポリシーを確認します。

## ウェブサイト DMG パイプライン

スクリプトは `scripts/release/` にあります。これらのデフォルトは、`APP_NAME`、`BUNDLE_ID`、`TEAM_ID`、`SIGNING_IDENTITY`、`NOTARY_PROFILE`、`VERSION`、`BUILD_NUMBER` などの環境変数で上書きできます。

構成された署名マシン上でのみ完全なパイプラインを実行します。

```bash
VERSION=<version> BUILD_NUMBER=<build> scripts/release/full_release_dmg.sh
```

パイプラインは、既存のビルド、署名、DMG、公証、および検証のスクリプトを構成します。検証ステップが成功するまで、その出力をリリース候補として扱います。

## Xcode 配布ターゲット

`XcodeProject/project.yml` から Xcode プロジェクトを生成し、承認された環境で適切な署名チームと機能を構成して、関連するターゲットをアーカイブします。生成された認証情報、プロビジョニング ファイル、または公証プロファイルをコミットしないでください。

## リリース後

1. リリース管理ポリシーに従って、不変バージョン タグと永続リリース ブランチを作成します。
2. リリース アーティファクトとチェックサムを公開します。
3. パブリック リリース レジストリは、アーティファクト URL が最終的なものになった後にのみ更新します。
4. レビュー済みのローカライズされたリリース ノートが提供されない限り、リリース ノートは英語で保存してください。
