# Руководство по выпуску Mac Vault

Это руководство соответствует зарегистрированным сценариям сборки. Он намеренно не содержит никаких личных данных для подписи, профиля нотариального заверения, пароля или данных учетной записи.

## Перед релизом

1. Запустите `swift test` из корня репозитория.
2. Установите версию выпуска и номер сборки в контролируемой конфигурации проекта/сборки.
3. Просмотрите руководство на английском языке, локализованные руководства и аудит перевода редактора.
4. Перед публикацией артефакта проверьте ветку выпуска, тег и политику контрольных точек.

## Конвейер DMG веб-сайта

Скрипты живут в `scripts/release/`. Их значения по умолчанию можно переопределить с помощью переменных среды, включая `APP_NAME`, `BUNDLE_ID`, `TEAM_ID`, `SIGNING_IDENTITY`, `NOTARY_PROFILE`, `VERSION` и `BUILD_NUMBER`.

Запускайте весь конвейер только на настроенной подписывающей машине:

```bash
VERSION=<version> BUILD_NUMBER=<build> scripts/release/full_release_dmg.sh
```

Конвейер объединяет существующие сценарии сборки, подписи, DMG, нотариального заверения и проверки. Рассматривайте его выходные данные как кандидата на выпуск до тех пор, пока этап проверки не завершится успешно.

## Цели распространения Xcode

Создайте проект Xcode из `XcodeProject/project.yml`, настройте соответствующую группу подписи и возможности в утвержденной среде, затем заархивируйте соответствующую цель. Не фиксируйте сгенерированные учетные данные, файлы подготовки или профили нотариального заверения.

## После релиза

1. Создайте неизменяемый тег версии и постоянную ветку выпуска в соответствии с политикой управления выпусками.
2. Опубликуйте артефакт выпуска и контрольную сумму.
3. Обновляйте общедоступный реестр выпусков только после того, как URL-адрес артефакта станет окончательным.
4. Сохраняйте примечания к выпуску на английском языке, если не предоставлена проверенная локализованная примечание к выпуску.
