# Mac Vault 출시 가이드

이 가이드는 체크인된 빌드 스크립트를 따릅니다. 여기에는 개인 서명 ID, 공증 프로필, 비밀번호 또는 계정 데이터가 의도적으로 포함되지 않습니다.

## 발매 전

1. 리포지토리 루트에서 `swift test`을 실행합니다.
2. 제어되는 프로젝트/빌드 구성에서 릴리스 버전과 빌드 번호를 설정합니다.
3. 영어 매뉴얼, 현지화된 매뉴얼, 편집자 번역 감사를 검토합니다.
4. 아티팩트를 게시하기 전에 릴리스 분기, 태그 및 마일스톤 정책을 확인하십시오.

## 웹사이트 DMG 파이프라인

스크립트는 `scripts/release/`에 있습니다. 기본값은 `APP_NAME`, `BUNDLE_ID`, `TEAM_ID`, `SIGNING_IDENTITY`, `NOTARY_PROFILE`, `VERSION` 및 `BUILD_NUMBER`을 포함한 환경 변수로 재정의될 수 있습니다.

구성된 서명 시스템에서만 전체 파이프라인을 실행합니다.

```bash
VERSION=<version> BUILD_NUMBER=<build> scripts/release/full_release_dmg.sh
```

파이프라인은 기존 빌드, 서명, DMG, 공증 및 확인 스크립트를 구성합니다. 확인 단계가 성공할 때까지 해당 출력을 릴리스 후보로 취급합니다.

## Xcode 배포 대상

`XcodeProject/project.yml`에서 Xcode 프로젝트를 생성하고 승인된 환경에서 적절한 서명 팀과 기능을 구성한 다음 관련 대상을 보관합니다. 생성된 자격 증명, 프로비저닝 파일 또는 공증 프로필을 커밋하지 마세요.

## 출시 후

1. 릴리스 관리 정책에 따라 변경 불가능한 버전 태그와 영구 릴리스 브랜치를 생성합니다.
2. 릴리스 아티팩트와 체크섬을 게시합니다.
3. 아티팩트 URL이 최종인 후에만 공개 릴리스 레지스트리를 업데이트하십시오.
4. 검토된 현지화된 릴리스 노트가 제공되지 않는 한 릴리스 노트를 영어로 유지하십시오.
