# ম্যাক ভল্ট রিলিজ গাইড

এই নির্দেশিকা চেক-ইন বিল্ড স্ক্রিপ্ট অনুসরণ করে। এতে ইচ্ছাকৃতভাবে কোনো ব্যক্তিগত স্বাক্ষরকারী পরিচয়, নোটারাইজেশন প্রোফাইল, পাসওয়ার্ড বা অ্যাকাউন্ট ডেটা নেই।

## মুক্তির আগে

1. রিপোজিটরি রুট থেকে `swift test` চালান।
2. নিয়ন্ত্রিত প্রকল্প/বিল্ড কনফিগারেশনে রিলিজ সংস্করণ এবং বিল্ড নম্বর সেট করুন।
3. ইংরেজি ম্যানুয়াল, স্থানীয় ম্যানুয়াল, এবং সম্পাদক অনুবাদ অডিট পর্যালোচনা করুন।
4. একটি আর্টিফ্যাক্ট প্রকাশ করার আগে রিলিজ শাখা, ট্যাগ এবং মাইলস্টোন নীতি যাচাই করুন।

## ওয়েবসাইট ডিএমজি পাইপলাইন

স্ক্রিপ্টগুলি `scripts/release/`-এ থাকে৷ তাদের ডিফল্টগুলি `APP_NAME`, `BUNDLE_ID`, `TEAM_ID`, `SIGNING_IDENTITY`, `NOTARY_PROFILE`, `NOTARY_PROFILE`, `NOTARY_PROFILE`, `VERSION`@@@006@@@@@@@@@@@@@@@@@@@@@@@`BUNDLE_ID``BUNDLE_ID`

সম্পূর্ণ পাইপলাইনটি শুধুমাত্র একটি কনফিগার করা সাইনিং মেশিনে চালান:

```bash
VERSION=<version> BUILD_NUMBER=<build> scripts/release/full_release_dmg.sh
```

পাইপলাইনটি বিদ্যমান বিল্ড, সাইনিং, ডিএমজি, নোটারাইজেশন এবং যাচাইকরণ স্ক্রিপ্টগুলি রচনা করে। যাচাইকরণ পদক্ষেপ সফল না হওয়া পর্যন্ত এটির আউটপুটকে রিলিজ প্রার্থী হিসাবে বিবেচনা করুন।

## Xcode বিতরণ লক্ষ্যমাত্রা

`XcodeProject/project.yml` থেকে Xcode প্রকল্প তৈরি করুন, অনুমোদিত পরিবেশে উপযুক্ত স্বাক্ষরকারী দল এবং ক্ষমতা কনফিগার করুন, তারপর প্রাসঙ্গিক লক্ষ্য সংরক্ষণ করুন। জেনারেট করা শংসাপত্র, প্রভিশনিং ফাইল বা নোটারাইজেশন প্রোফাইলের প্রতিশ্রুতি দেবেন না।

## মুক্তির পর

1. রিলিজ-ম্যানেজমেন্ট নীতি অনুযায়ী অপরিবর্তনীয় সংস্করণ ট্যাগ এবং স্থায়ী রিলিজ শাখা তৈরি করুন।
2. রিলিজ আর্টিফ্যাক্ট এবং চেকসাম প্রকাশ করুন।
3. আর্টিফ্যাক্ট URL চূড়ান্ত হওয়ার পরেই পাবলিক রিলিজ রেজিস্ট্রি আপডেট করুন৷
4. রিলিজ নোটগুলি ইংরেজিতে রাখুন যদি না একটি পর্যালোচনা করা স্থানীয় রিলিজ নোট সরবরাহ করা হয়।
