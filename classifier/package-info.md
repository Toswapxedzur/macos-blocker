# classifier — shared Vault Classifier and Activity components

> 🤖 **AI protocol:** Read `../package-info.md` (Mac Vault), `../../package-info.md` (group), the group `AGENTS.md`, and `../../misc/project-memory/PROJECT-MEMORY.md` before working here. Update this file when the folder changes. Never delete without owner consent; keep secrets out of git.

- **What:** a **component of desktop Vault, not a separate product** (owner decision 2026-09-19; it has no version of its own — it arrived with Mac Vault 1.0.0). Mac Vault links the `VaultClassifierApp` library, starts the tagging service at launch (`VaultClassifierPage.shared.start()` in `BlockerAppDelegate`) and shows it as the **Classifier** page of its window (`BlockerMainView`). A local-first portable Swift package that classifies collected public content (YouTube-first) on-device with llama.cpp, keeps per-video results and user corrections, and pushes tags to the extension for content-based blocking. In-process it joins Mac Vault's local hub as a peer (dev `ws://127.0.0.1:18787`); the shared backend never hosts a second hub. Optional provider profiles and grounded correction retrieval. **Unreleased**; no default model is bundled.
- **Windows port boundary (2026-10-02):** `VaultClassifierWorker` hosts the same `VaultClassifierViewModel` behind a bounded JSON-lines pipe owned by the .NET Windows host. It reuses the exact action/MCP/snapshot, collection/tagging/correction, provider research, model download and engine-registry paths. `VaultActivityCore` holds the six canonical Activity store/dashboard/group/wire/accumulator sources; Mac Core re-exports this target. `CVaultWindows` supplies current-user protected ACLs, DPAPI for the backup-code verifier, secure randomness, source-icon JPEG conversion and fail-closed package cleanup. Production/development are separate. Host assets come from the canonical Mac scene and translations; Windows source-icon URLs are mapped to the host's private WebView2 resource route. Packaging/tests live in `windowsBlocker/scripts/classifier-worker/`; `Tests/Worker/interactive_pipe.py` verifies small request replies before stdin closes on mini1. Windows builds do not include AppKit/WebKit or the Apple-signature native-messaging host.
- **Classifier group platforms (owner 2026-10-01):** choose at least one classifiable platform when creating a group; after creation the checklist is read-only. An empty selection is refused in both the dialog and shared create action. The `configureClassifierType` web/MCP action changes only the name and rejects a payload that tries to set `applicablePlatformIDs`. To change the platform set, create another group; the existing group's tag tree and classifications stay with it until deliberately deleted.
- **Tagging activation (owner 2026-10-01):** Classifier Settings owns the global enable switch; every group starts active and has a visible Pause/Resume button. Pause hides its pills and stops new automatic classification. Recording remains in Activity. The native status/push path activates already-open pages after group creation; browser blocking filters and retired extension classifier settings do not gate tagging.
- **Group configuration (owner 2026-10-01):** model tier/download/status, Strict↔Broad, house rules and research remain directly visible. More contains only optional Minimum tags (0–3) and Maximum tags (1–3); each empty field follows that bound from the group's Strict↔Broad position. Explicit bounds survive dial changes; invalid effective min > max is refused. Inputs autosave and preserve drafts/focus. Group deletion is permanent after the second click; Trash and recovery snapshots are retired, and old Trash state is ignored safely.
- **Research setup (owner 2026-10-01):** API keys live in Settings directly above Grounded research. Groups offer Set up grounded research when provider/key/model are missing, Enable grounded research when global consent is off, and On when ready. Setup choices open and highlight the relevant Settings fields without saving the group On or enabling consent. Knowledge shows the selected lookup provider/model and a setup link. The research model is selected from a searchable, bounded list fetched explicitly for that provider; Fetch/Fetching/Refresh/Retry states reuse its existing local model cache. Missing saved choices stay visible as unavailable rather than being replaced.
- **Live editing (owner 2026-10-01):** ordinary Classifier edits save automatically through the existing web actions. Choices save on change; text saves after 300 ms or on leaving its field. Drafts, caret and input composition survive incoming snapshots. Creation, deletion, Probe, downloads and backup unlock are explicit actions. Changing house rules or strictness does not reload the model engine; each group tier loads lazily through the shared engine registry. `Tests/WebUI/autosave.mjs` drives the actual page against synthetic state in a mini1 test browser.
- **Storage (2026-09-30):** `~/Library/Application Support/VaultClassifier[-Development]/state.json` holds settings, types, trees, knowledge and classifications; collected entries live beside it in `collected/<dataset>/<platform>/<yyyy-MM-dd>.json` (by first-seen day; a save rewrites only changed days). Each platform keeps its entries for its Keep (Collection page; default = all platforms 180 days; safety bound 30 000 per platform). Knowledge creators keep their pictures in `creator-pictures/`.
- **Its page is a scene of Mac Vault's one web view (2026-09-28):** `WebAssets/app.js`/`app.css`/`strings.js` run in a shadow root of Mac Vault's document (the host's `scenes.js` provides `window.VaultScenes.scope("classifier")`; the script looks up and listens only inside it; `:host` stands for html/body in the CSS). `VaultClassifierPage.install(in:)`/`attach(_:)`/`webAssetsDirectory` hand the host the message handler, the source-icon scheme and the files; the page no longer has its own web view, `index.html` or scene-switch forwarding.

Chromium reads the manifest from `<user-data-dir>/NativeMessagingHosts/` (copy `com.adamancia.vault.local_hub.development.json` there). - **Settings shape (owner decision 2026-09-23 — "replace ALL parameters with two dials"):** the local model has exactly two user controls, `SpeedQualityDial` (Fast = Qwen2.5 3B / Balanced = 7B, default / Best = 14B; `LocalModelCatalog` holds only these three) and `StrictnessDial` (1 one tag · 2 up to three at 0.97 sureness · 3 default, 0.90 · 4 0.85 · 5 like 4 and never decline), both in `Sources/VaultClassifierCore/VaultDials.swift`; plus independent house rules and each type's own tag tree. Owner decision 2026-10-01 retires global dials: each group stores concrete `localModel: LocalLLMSettings`. Its core tier/download cards, five strictness rows and house rules stay visible; More contains optional tag-count bounds. Global controls/save action and inheritance are removed. Existing effective values reconcile once from retired saved globals/overrides; new groups start Balanced/Balanced with no rules. Model files and the two-resident-tier registry are shared; runtime loading/loaded/failed status follows each group's selected file; a missing selected file yields provisional stub results, never another tier. Research is on/off + provider/model (`ResearchSettings`), per type only on/off/follow (`ClassifierTypeAsset.researchEnabled`). Everything else (context/batch tokens, GPU, output cap, temperature 0, confidence thresholds, resident models, research budgets 6/min · 10k tokens/day, cooldown 24 h, creator trigger score 3 / half-life 14 d, knowledge TTL/limit) is a `static let` constant on those structs. Presets (`VaultPreset`) are deleted; pre-dial state keys decode to the nearest position and never re-encode (tests: `LocalModelSettingsTests`, `LegacyStateDecodeTests`, `WorkspaceAssetsTests`). Measured positions (7B, research on, 450-video library): correct 57/64/67/68/72 %, wrong-tag share 9/14/16/18/23 %.
- **Nothing below the dials is exposed to users (owner decision 2026-09-23).** The only lower-level surface is developer environment variables, never UI: `ADAMANCIA_VAULT_ENVIRONMENT` (development / production state dir), `ADAMANCIA_VAULT_LLM_MODEL` (explicit GGUF path when the dial's file is absent), `ADAMANCIA_VAULT_DEV_LOG`, `ADAMANCIA_VAULT_TAG_TEST`, `VAULT_DECODE_TIMING=1` (per-batch engine timing on stderr), `VAULT_NAMES_MIN_JOINT` (overrides the extra-tag sureness for eval sweeps), `VAULT_NAMES_LOG=1`, `VAULT_REPLY_FORMAT=json|names`, `VAULT_NO_FORCED_SPANS`, `VAULT_ARRIVAL_WINDOW_MS` (the coalescer's idle arrival window, default 75; a lone video pays it in full), `VAULT_SNAPSHOT_ALWAYS=1` (rebuild the web snapshot even while the Classifier page is hidden — the 2026-09-23 default skips it: ~90 ms build + ~60 ms serialise of a 1.5 MB payload on the main thread per burst). Everything else is a `static let` — change the constant, don't add a knob.
- **MCP surface (owner 2026-09-23, "1:1 parity"):** `Sources/VaultClassifierApp/VaultClassifierViewModel+MCP.swift` exposes the page's two halves — `mcpSnapshot(section:)` (the same `webSnapshot()` the page renders: nil = compact overview, `all`, a top-level section, or `assets.<key>`) and `mcpPerform(action:data:)` (= `performWebAction`, same validation) — plus `ClassifierWebActionCatalog` (every action + the data keys it reads; `ClassifierMCPTests` parses the dispatcher source and fails when the catalog drifts). Mac Vault publishes them as the MCP tools `classifier_state`, `classifier_action`, `classifier_actions` (`macosBlocker/Sources/MacBlockerAppFeature/ClassifierMCPTools.swift`, main-actor hop). A new page action is automatically an MCP action once it has a catalog entry.
