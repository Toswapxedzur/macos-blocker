# classifier — the Vault Classifier component of Mac Vault (on-device tagging + its page)

> 🤖 **AI protocol:** Read `../package-info.md` (Mac Vault), `../../package-info.md` (group), the group `AGENTS.md`, and `../../misc/project-memory/PROJECT-MEMORY.md` before working here. Update this file when the folder changes. Never delete without owner consent; keep secrets out of git.

- **What:** a **component of Mac Vault, not a product** (owner decision 2026-09-19; it has no version of its own — it arrived with Mac Vault 1.0.0). Mac Vault links the `VaultClassifierApp` library, starts the tagging service at launch (`VaultClassifierPage.shared.start()` in `BlockerAppDelegate`) and shows it as the **Classifier** page of its window (`BlockerMainView`). A local-first macOS Swift package that classifies collected public content (YouTube-first) on-device with llama.cpp, keeps per-video results and user corrections, and pushes tags to the extension for content-based blocking. In-process it joins Mac Vault's local hub as a peer (dev `ws://127.0.0.1:18787`); the standalone shell can still host the hub itself. Optional explicit LLM Assist providers and grounded correction retrieval. **Unreleased**; no default model is bundled.
- **Git:** lives in Mac Vault's repo (`Toswapxedzur/macos-blocker`) under `classifier/`, merged 2026-09-19 with `git subtree add` — all 246 commits and their hashes are preserved. The old `Toswapxedzur/vault-classifier` repo is archived. `git log -- classifier/` covers history after the merge; for earlier history log the old root paths (e.g. `git log -- Sources/VaultClassifierCore`).
- **Build/test/run:** `swift build`, `swift test`; dev launch is **`../run-mac-vault.sh`** — the classifier ONLY runs inside Mac Vault now (the standalone `VaultClassifierShell` and its `run-vault-classifier.sh` / `scripts/package-macapp.sh` were deleted 2026-09-20; the classifier never hosts the hub, it joins Mac Vault's ConnectionHub as a client). `scripts/bundle-llama-runtime.sh` makes an .app self-contained for llama.cpp (used by Mac Vault's `scripts/release/build_app.sh`); `scripts/install-dev-native-host.sh` installs the dev Native Messaging host.

- **Settings shape (owner decision 2026-09-23 — "replace ALL parameters with two dials"):** the local model has exactly two user controls, `SpeedQualityDial` (Fast = Qwen2.5 3B / Balanced = 7B, default / Best = 14B; `LocalModelCatalog` holds only these three) and `StrictnessDial` (1 one tag · 2 up to three at 0.97 sureness · 3 default, 0.90 · 4 0.85 · 5 like 4 and never decline), both in `Sources/VaultClassifierCore/VaultDials.swift`; plus house rules (global + per type) and each type's own tag tree. Both dials exist globally (`LocalLLMSettings`) and a type may hold its own position (`LocalModelOverrides.speedQuality/strictness`, nil = follow global). Research is on/off + provider/model (`ResearchSettings`), per type only on/off/follow (`ClassifierTypeAsset.researchEnabled`). Everything else (context/batch tokens, GPU, output cap, temperature 0, confidence thresholds, resident models, research budgets 6/min · 10k tokens/day, cooldown 24 h, creator trigger score 3 / half-life 14 d, knowledge TTL/limit) is a `static let` constant on those structs. Presets (`VaultPreset`) are deleted; pre-dial state keys decode to the nearest position and never re-encode (tests: `LocalModelOverridesTests`, `WorkspaceAssetsTests`). Measured positions (7B, research on, 450-video library): correct 57/64/67/68/72 %, wrong-tag share 9/14/16/18/23 %.
- **Nothing below the dials is exposed to users (owner decision 2026-09-23).** The only lower-level surface is developer environment variables, never UI: `ADAMANCIA_VAULT_ENVIRONMENT` (development / production state dir), `ADAMANCIA_VAULT_LLM_MODEL` (explicit GGUF path when the dial's file is absent), `ADAMANCIA_VAULT_DEV_LOG`, `ADAMANCIA_VAULT_TAG_TEST`, `VAULT_DECODE_TIMING=1` (per-batch engine timing on stderr), `VAULT_NAMES_MIN_JOINT` (overrides the extra-tag sureness for eval sweeps), `VAULT_NAMES_LOG=1`, `VAULT_REPLY_FORMAT=json|names`, `VAULT_NO_FORCED_SPANS`, `VAULT_ARRIVAL_WINDOW_MS` (the coalescer's idle arrival window, default 75; a lone video pays it in full), `VAULT_SNAPSHOT_ALWAYS=1` (rebuild the web snapshot even while the Classifier page is hidden — the 2026-09-23 default skips it: ~90 ms build + ~60 ms serialise of a 1.5 MB payload on the main thread per burst). Everything else is a `static let` — change the constant, don't add a knob.
- **MCP surface (owner 2026-09-23, "1:1 parity"):** `Sources/VaultClassifierApp/VaultClassifierViewModel+MCP.swift` exposes the page's two halves — `mcpSnapshot(section:)` (the same `webSnapshot()` the page renders: nil = compact overview, `all`, a top-level section, or `assets.<key>`) and `mcpPerform(action:data:)` (= `performWebAction`, same validation) — plus `ClassifierWebActionCatalog` (every action + the data keys it reads; `ClassifierMCPTests` parses the dispatcher source and fails when the catalog drifts). Mac Vault publishes them as the MCP tools `classifier_state`, `classifier_action`, `classifier_actions` (`macosBlocker/Sources/MacBlockerAppFeature/ClassifierMCPTools.swift`, main-actor hop). A new page action is automatically an MCP action once it has a catalog entry.
